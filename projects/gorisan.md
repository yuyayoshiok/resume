# Gorisan（ゴリさん）— 関西弁AIパーソナルトレーナー LINE Bot

> 「筋肉は裏切らへん！💪」— 熱血・関西弁キャラのAIトレーナーが、食事写真の解析から運動記録、応援メッセージまで担当し、ダイエットの「継続」を支える LINE Bot。

友人と2人で使う設計で、**お互いの記録が相手への応援通知になる**。

- **稼働状況**: 2026年7月〜／本番稼働中
- **主インターフェース**: LINE（トーク画面＋ユーザー別のボタンメニュー）

---

## 概要

「AIに叱られる」のではなく「アニキに褒められる」体験を目指したダイエット支援Bot。

行動科学の知見（スモールステップ・全肯定・完璧主義の禁止）をキャラクター設計に落とし込み、**記録のハードルを限界まで下げる**ことに全振りしている。

設計の軸は3つ:

1. **入力ハードルゼロ** — 食事は写真1枚、体重・歩数・筋トレは「⚪︎.⚪︎kg」「5000歩歩いた」のような普通の文章をAIが理解して自動記録。専用フォームやコマンドを覚える必要がない
2. **キャラクター × 行動科学** — 「スクワット1回でOK」「休むのも勇気やで」など、0を1にすることを称賛する全肯定スタンスをAIへの指示文で一貫させる
3. **2人で続ける仕組み** — 片方が記録するともう一方へ応援メッセージが飛ぶ「相互奮起通知」、3日間記録がないと心配メッセージが届く「サボり検知」で、脱落を防ぐ

---

## 主な機能

### 対話機能（LINEでのやりとり）

| 機能 | 内容 |
|------|------|
| 食事画像解析 | 写真を送るとAI（Gemini）がメニューを推定し、カロリーと栄養バランス（タンパク質・脂質・炭水化物）を解析。時間帯（夕食は大皿の可能性等）も考慮 |
| テキスト食事記録 | 「カツ丼食べた」だけで記録。「親子丼やった」と訂正すると即再計算 |
| 普通の文章で記録 | AIが文章の意図を読み取って数値を取り出し、データベースへ保存。体重・歩数・筋トレ（種目/重量/セット/回数）に対応 |
| グラフ生成 | 直近30日の体重・歩数の推移をグラフ画像で返信 |
| 相談・質問への回答 | 筋トレ方法などの相談には、AIがGoogle検索で裏付けを取りながら回答 |
| ゴール自動切替 | 目標体重の達成を検知すると「ダイエットモード」から「筋トレモード」へ自動移行し、ボタンメニューも差し替え |

### 自動で動く機能（決まった時刻・データ着信で起動）

| 機能 | トリガー | 内容 |
|------|------|------|
| タスク通知 | 毎朝7時 | 今日やることをリマインド |
| サボり検知 | 毎日11時 | 3日間記録がないユーザーへ心配メッセージ |
| マイルストーン | 体重記録時 | 「-2kg達成」などの節目を検知して祝福 |
| 週次レビュー | 日曜21時 | 1週間の体重・歩数・食事を総括 |
| 月次チャレンジ | 月初/月末 | 月ごとの目標設定と達成判定 |
| 日記への自動反映 | ヘルスデータ着信時 | Apple Watch経由の体重・歩数データが届いたら、メモ帳（Obsidian）の日記へ自動転記 |

### ソーシャル機能

- **相互奮起通知**: どちらかが体重・食事・運動を記録すると、相手に「記録したで！」と応援メッセージが届く。本人への返信を待たせないよう、裏側で並行して送信する作り
- **オンボーディング**: 初めて友だち追加したときに、目標や現在の状態をヒアリングする案内フロー

## 技術スタック

- **言語**: Go 1.21+（Webフレームワークを使わない、標準機能だけの軽量な単一プログラム）
- **AI**: Gemini 3.1 Flash Lite（文章の理解・写真の解析・Google検索と連携した回答）
- **インフラ**: Cloud Run（Googleの、サーバー管理不要でプログラムを動かせるサービス）+ Cloud Scheduler（クラウド版の目覚まし時計）+ Pub/Sub（クラウド内の「お知らせ」配達便）
- **データ保存**: Firestore（ユーザー情報・記録データのデータベース）/ Cloud Storage（食事画像・健康データの保管庫）
- **秘密情報の管理**: Secret Manager（APIキーなどを安全に保管。アクセス回数を減らすキャッシュ付き）
- **外部連携**: LINE Messaging API（メッセージ受信・送信・ボタンメニュー）

## アーキテクチャ（構成）

```
gorisan_go/                      1つのCloud Runサービスとして稼働
├── main.go                      入口の交通整理・定時実行の受け口
├── line_handler.go / client     LINEのメッセージ受信・返信・プッシュ送信
├── intent_classifier.go         AIによる「この文章は何の記録か」の判定
├── feature_food_analyzer.go     食事画像の解析
├── feature_food_text.go         テキストでの食事記録・訂正
├── feature_workout.go           筋トレの記録（対話の流れを記憶）
├── feature_mutual_motivation.go 相互奮起通知
├── feature_rag.go               相談への回答（Google検索連携）
├── feature_chart.go / report    グラフ生成・各種レポート
├── cron_*.go                    サボり検知 / 週次 / 月次 / 日記への自動反映
├── user_service.go              複数ユーザーの管理（本人 / 友人）
└── onboarding_handler.go        初回セットアップの案内
```

### データフロー例（相互奮起通知）

```
友人がLINEで「今日3000歩」と送信
  → AIが「歩数の記録だ」と判定して数値を取り出す
  → データベースに保存 ＋ 本人へ即返信（褒める）
  → 裏側で並行して、相手（自分）へ応援メッセージを送信
```

## 技術的な見どころ

- **データ着信をきっかけに動くイベント設計**: Apple Watchの健康データがクラウドの保管庫に書き込まれた瞬間、その「お知らせ」を受けて日記への転記が自動で走る。ファイルのパスから日付を読み取る作りなので、**データの到着が遅れても・同じお知らせが2回届いても、正しい日付に1回だけ正しく処理される**
- **クラウド費用を抑える工夫**: 秘密情報（APIキー等）の取得結果をプログラム内に記憶し、起動中のアクセスを1回に制限。呼び出し課金のあるサービスへの無駄なアクセスを削減
- **ユーザー追加に強い設計**: 「誰からのメッセージか」の判定をデータベース照会ベースにし、友人が増えても設定変更なしで自動対応（照会結果は5分間記憶して負荷も抑制）
