# x-yuya（ラジオ機能）— AIパーソナリティ2人のポッドキャスト自動生成

> 自分のメモ帳（Obsidian）に溜めた思考ログや日記を素材に、AIがラジオ番組の台本を書き、2人のAI話者が掛け合いで読み上げて、毎日自動で配信する——**人の手を一切借りずに、毎日ポッドキャストが1本できあがる**システム。

---

## 概要

毎日決まった時刻にAIが起動し、2人トーク形式のラジオ音声を自動生成・配信する。番組は2チャンネル:

| チャンネル | タイプ | 実行 | 尺 | 特徴 |
|-----------|--------|------|----|------|
| **BGM** | 最新ニュース型 | 毎日00:00 自動実行 | 約8-10分 | Web検索を使って最新の話題を取り上げる |
| **価値観ラヂオ** | 内省・深掘り型 | 手動／まとめて生成 | 約10分（2部構成） | メモ帳を精読し、過去に話したテーマは避ける |

### 処理の流れ
```
入力: メモ帳（思考ログ・ブックマーク・日記）＋ Web検索（BGMのみ）
  ↓ AI（Codex）が2人の掛け合い形式の台本を生成（計4000-5000字）
  ↓ 音声合成AI（AivisSpeech）がセリフを1行ずつ読み上げ
  ↓ 音声ファイルを連結 → 音量を自動調整 → MP3化
  ↓ クラウドの保管庫（Cloudflare R2）へアップロード
出力: 番組リストへ追加 → 自作ダッシュボード（Kanban）のラジオプレイヤーで再生できる
```

---

## 技術スタック

- **台本生成**: Codex（OpenAIのAI）をプログラムから自動起動。
- **音声合成**: AivisSpeech（日本語テキストを音声に変換。オープンソース・無料で回数制限なし）。話者の声は設定で選択可能
- **言語/実行**: Python 3.11 / Bash
- **インフラ**: Cloudflare R2（音声ファイルの保管庫）/ GitHub Actions（毎日決まった時刻にプログラムを自動実行する仕組み）
- **音声処理**: ffmpeg（音声の結合・音量調整・MP3変換を行う定番ツール）

### 番組の履歴管理
- 過去に取り上げたテーマ・使った素材を記録して、同じ話の繰り返しを防止
- 価値観ラヂオはエピソード番号を自動で連番管理

## 主要ファイル

```
scripts/
├── generate-codex.py     台本生成のメイン処理
│   ├── メモ帳から思考ログ・ブックマーク・日記を収集
│   ├── 過去に使ったテーマ・素材を避ける重複チェック
│   └── チャンネル別にAIへの指示文を組み立て
├── tts-aivis.py          音声合成（台本 → MP3）
│   ├── 台本を話者1/話者2のセリフに分解
│   ├── 1行ずつ音声合成して連結
│   └── 番組リスト（index.json）へ新エピソードを追加
└── sync-codex-auth.sh    AIのログイン情報を自動更新（下記「見どころ」参照）

.github/workflows/radio.yml  毎日00:00の自動実行設定
```

## 技術的な見どころ

- **AIを差し替えられる設計**: 台本担当のAIを Codex / Claude / Gemini から切り替え可能。特定のAIサービスに依存せず、旧システムからの段階的な乗り換えも実現した
- **同じ話を繰り返さない工夫**: 過去に使ったメモ・テーマを履歴ファイルに記録し、素材選びの段階で二重チェック。毎日配信しても内容が被らない
- **配信履歴が消えないアップロード手順**: クラウド上の番組リストを「既存を取得 → 新エピソードを追記 → アップロードし直す」の順で更新し、うっかり上書きして履歴が消える事故を防止
- **自宅PCでもクラウドでも同じように動く**: 実行環境の違いを設定（環境変数）で吸収し、同じプログラムをローカル実行と自動実行の両方で使い回せる
- **ログイン切れの自動予防**: 数日で期限切れになるAIの認証情報を、Macの定期実行機能で1日4回自動更新。深夜の自動配信が「ログイン切れ」で止まらないようにした
- **待ち時間の短縮**: 音声合成用の声データ（初回は5-10分かかるダウンロード）を保存して再利用し、毎日の自動実行を高速化
- **無料で量産できる音声合成**: オープンソースの音声合成を採用したことで、クラウドサービスの利用上限や課金から解放。ローカルPCなら1日100本規模の生成も可能
